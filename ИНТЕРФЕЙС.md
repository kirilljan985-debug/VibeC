# 🔌 ИНТЕРФЕЙС.md — контракт стыковки бэка и фронта VibeC

**Это главный документ двухагентной разработки.** Проект разделён на две зоны:

| Зона | Папки | Ведёт |
|---|---|---|
| 🧠 **Бэк** | `server/`, `tests/` | ZCode — сканер папки «обучение», HTTP API, хранилище прогресса |
| 🎨 **Фронт** | `front/` | GPT — дашборд, списки уроков, просмотр, поиск, отметки прогресса |

**Прочти перед любой правкой.** Изменять этот файл можно только по договорённости обоих агентов через продюсера (студента). Версия контракта: **v1.1** (10.10.2026).

---

## Принцип разделения

- **Бэк не знает про красивое.** В `server/` нет ни строчки разметки интерфейса (кроме временной страницы-заглушки, которая исчезнет, когда приедет `front/index.html`).
- **Фронт не сканирует файлы.** Фронт никогда не читает папку «обучение» напрямую и не парсит HTML уроков: каталог, поиск и прогресс — только через API. Урок показывается целиком в iframe (`/content/…`).
- Следствие: бэк проверяется тестами без браузера, фронт перекраивается без правки сервера.

## Как фронт получает данные

Один origin: фронт отдаётся тем же сервером с `/`, поэтому запросы простые — `fetch("/api/...")`, без CORS-настроек (CORS `*` на API включён на случай разработки фронта отдельным инструментом).

### Эндпоинты (реализованы, проверены тестами и на живой папке)

| Метод | Путь | Что отдаёт |
|---|---|---|
| GET | `/api/catalog` | Весь каталог: треки с уроками, экспресс-курс, справочники, материалы, документы, записи прогресса. **Скан живой папки на каждый запрос** — новые уроки появляются сами, отдельного «обновить» не нужно |
| GET | `/api/lesson/{id}` | Урок по id + соседи `prev_id`/`next_id` (общий порядок: треки → экспресс) + его отметка прогресса |
| GET | `/api/search?q=…` | Полнотекстовый поиск по урокам (регистр не важен), сниппеты с «…», лимит 30 |
| GET | `/api/progress` | `{"items": {lesson_id: {status, updated_at, note}}}` — отметки пользователя |
| POST | `/api/progress` | Поставить: `{"lesson_id":"base-0001","status":"done","note":"…"}` — lesson_id обязан быть в каталоге, иначе 404; снять: `{"lesson_id":"base-0001","status":null}` (разрешено для любого id — так чистятся записи исчезнувших уроков). Ответ всегда содержит обновлённые `items` целиком |
| GET | `/api/meta` | Статус сервера: версия, `content_root_exists`, `front_present`, `counts` |

Ошибки: JSON `{"error": "…"}` и честные коды — 400 (плохой запрос/статус), 404 (нет урока/эндпоинта/файла), 500 (папка обучения недоступна).

### Статика

| Префикс | Источник | Зачем фронту |
|---|---|---|
| `/content/<путь>` | папка «обучение», зеркало 1:1 | Уроки: `url` из каталога — в `<iframe src>` или в новую вкладку. Квизы, флеш-карты и стили внутри уроков работают (относительные ссылки на `компоненты/` сохраняются) |
| `/`, `/<файл>` | папка `front/` | `index.html` и статика фронта. Пока `front/index.html` нет — сервер показывает страницу-заглушку со статусом API |

За корень не выйти (`..` и скрытые файлы/папки блокируются — проверено тестами).

## Форматы (ключевые поля)

`GET /api/catalog` (сокращённо — полный пример всегда можно увидеть запросом):

```json
{
  "api": "vibec", "version": 1, "generated_at": "2026-10-10T…",
  "content_root": "C:\\Users\\…\\обучение",
  "tracks": [
    {
      "id": "track-b", "title": "Трек Б · Python", "description": "…",
      "lessons": [
        {
          "id": "track-b-0005", "number": "0005",
          "title": "Переменные в деле: первые строки кода",
          "kicker": "Урок 0005 · Трек Б · Python · ~15 минут",
          "summary": "Первый урок трека Б…",
          "interactive": ["quiz"],
          "file": "уроки/трек-Б-питон/0005-peremennye-v-dele.html",
          "url": "/content/уроки/трек-Б-питон/0005-peremennye-v-dele.html",
          "seed_status": "done", "seed_label": "пройден: game.py написан и запущен…"
        }
      ]
    }
  ],
  "express_course": { "id": "express", "lessons": [ … ], "intro_url": "/content/…/index.html", "glossary_url": "/content/…/glossary-interactive.html" },
  "references":  [ { "id": "glossary-core", "title": "…", "description": "…", "url": "/content/…" } ],
  "materials":   [ { "id": "progit-ru", "name": "progit-ru.pdf", "url": "/content/материалы/progit-ru.pdf", "size_bytes": … } ],
  "documents":   [ { "id": "МИССИЯ", "title": "🎯 Миссия", "url": "/content/документы-курса/МИССИЯ.md" } ],
  "progress_notes": [ { "id": "0001-…", "number": "0001", "title": "…", "url": "/content/…" } ],
  "counts": { "tracks": 3, "lessons": 11, "express_lessons": 6, "references": 3, "materials": 1, "documents": 4, "progress_notes": 7 }
}
```

**Статус урока = слияние двух источников** (делает фронт):
1. `seed_status` / `seed_label` — из таблицы «Статус» в `обучение/ПАМЯТЬ.md` (ведёт преподаватель). Значения: `done` ✅ / `reading` 📖 / `next` ⏳ / `planned` ❓
2. Отметка пользователя из `GET /api/progress` — **перекрывает семя**, если есть. Разрешены: `not-started`, `in-progress`, `done` (+ необязательная `note`)

Идентификаторы уроков стабильны: `{трек}-{номер}` (`base-0001`, `track-a-0003`, `track-b-0005`, `express-0001`). Новая подпапка в `уроки/` становится новым треком автоматически (id = `track-<имя папки>`).

## Границы файлов (ownership)

```
server/, tests/   ← только ZCode
front/            ← только GPT (index.html, стили, скрипты фронта)
data/             ← runtime бэка (progress.json), никем не редактируется руками
ИНТЕРФЕЙС.md      ← меняется только по договору (оба агента через продюсера)
ПАМЯТЬ/ПЛАН/README ← продюсер + ZCode
```

## Протокол при смене контракта

Фронту нужно поле/эндпоинт, которого нет → GPT не выдумывает его и не парсит файлы сам: GPT говорит продюсеру → продюсер передаёт ZCode → ZCode добавляет в API и в этот файл (версия +1) → GPT использует. Пока фронт может фильтровать/сортировать каталог у себя — это нормально, логика *данных* (не файлов) на фронте не запрещена.

- v1.0 (10.10.2026): создан. 6 эндпоинтов, статика `/content/*` и `/`, форматы JSON, правила слияния статусов, границы зон.
